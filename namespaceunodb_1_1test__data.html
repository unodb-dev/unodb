Detailed Description

Namespace for the shared ART test data and key encoding helpers.

It is not part of the public API, and it may change at any time.

)
constexprnoexcept

Copy an encoded key into caller-owned storage; the returned view is valid for the lifetime of buf.

Precondition
kv.size() <= buf.size(). The copy is bounded by kv, not by buf, and the returned view's length is kv.size(), so an oversize key both overruns buf and yields a view past its end. Enforced only by an assert, which NDEBUG compiles out.

Encode a 17-byte key: 0xAA × 10, then byte10, then 0xAA × 5, then last.

Two keys sharing byte10 differ only at byte 16: two single-child chain levels above the inode that branches on byte 16. A key with a different byte10 diverges inside that inode's prefix and splits it, leaving an inode branching on byte10 with one byte-16 inode per byte10 value below it.

◆ too_long_key_view()

unodb::key_view unodb::test_data::too_long_key_view ( )
inlinenoexcept

A key view too long to be stored in any tree, for rejection tests.

Warning
Only the length is real — the view spans a single byte. Never read through it; pass it only to APIs that reject it by size before touching the data (currently only insert paths check the size). Deliberately a function rather than a constexpr variable, despite CONTRIBUTING.md's rule: under _GLIBCXX_DEBUG libstdc++'s std::span constructor forms ptr + count, and constant-initializing that offset past a single-byte object is not a core constant expression, which Clang rejects outright.

◆ chain_key_filler

constexpr auto unodb::test_data::chain_key_filler = std::uint64_t{0x4242424242424242ULL}
inlineconstexpr

Filler word giving consecutive key bytes a shared pattern, forcing key-prefix chains: keys sharing more than key_prefix_capacity (7) bytes need a chain of internal nodes because the dispatch byte after the stored prefix is the same for all of them.

Only the sharing matters, not the value: the zero words in make_key_18 and make_key_26 force chains the same way. 0x42 keeps filler bytes apart from those zero words and from chain_key_filler_alt in a dump.
