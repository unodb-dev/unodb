◆ must_not_allocate()

template<typename TestAction>
requires (!std::is_void_v<std::invoke_result_t<const TestAction&>>)
std::invoke_result_t< const TestAction & > unodb::test::must_not_allocate ( const TestAction & test_action)
nodiscardnoexcept

Test that given action does not allocate heap memory.

This function configures the allocation failure injector to fail on the first allocation and executes the provided test action. If the action tries to allocate memory, it will throw std::bad_alloc. If it completes successfully, we know it didn't allocate. The injector is reset on every exit from the pinned scope: a normal return, a fatal Google Test assertion inside test_action, and the injected std::bad_alloc alike. Under NDEBUG the injector compiles away, so the pin is not enforced and test_action simply runs: the check is skipped rather than answered wrongly.

Warning
Armed scopes must not nest on one thread: doing so trips unodb::test::fail_on_nth_allocation_guard's debug assert, which aborts the process instead of reporting a test failure.
A noexcept test_action does not unwind: the injected std::bad_alloc crosses its own noexcept boundary, so a violated pin terminates the process instead of producing an observable std::bad_alloc. The QSBR accessors pass such actions deliberately, as CONTRIBUTING.md asks for noexcept on anything that cannot throw in a release build, which is what these are once this guard compiles away.
An assertion inside test_action runs armed: its failure escapes as std::bad_alloc, losing the diagnostic. Assert on the result instead.
This function affects global state. No other threads should allocate memory during execution of this function, as the allocation failure injector is global.

◆ release_after_missed_park()

template<class... Points>
void unodb::test::release_after_missed_park ( unodb::detail::thread_sync & park_sync,
unodb::detail::thread_sync & resume_sync,
Points &... points )

Release the interleaved thread of a parked run whose parked operation returned without parking, once the parked thread has joined.

The interleaved thread must still be waiting on park_sync, and must notify resume_sync once, after its operation returns. Each of points is disarmed first, since the interleaved operation may pass it and would then park on itself or wait for a release that never comes. The final wait consumes that notify, so that both syncs end reset, as ~thread_sync asserts. Report the miss only once the interleaved thread has joined too: under –gtest_throw_on_failure the report throws, and unwinding past a joinable thread would terminate the run before the exception could reach a handler.

◆ run_parked_interleaving()

template<unsigned ParkHit = 1, class Parked, class Interleaved>
unsigned unodb::test::run_parked_interleaving ( unodb::detail::sync_point & point,
const Parked & parked,
const Interleaved & interleaved )
nodiscard

Run parked on one QSBR thread, stopped at the ParkHit-th hit of point, while interleaved runs to completion on another.

Each callable runs inside a unodb::quiescent_state_on_scope_exit scope. parked must hit point at least ParkHit times, since interleaved waits for that park: if parked returns first, the test fails instead of hanging, and interleaved then runs without a park. parked resumes only once interleaved returns, so interleaved must not need anything parked holds at point: it spins on a node parked has write-locked, even one it only descends through, and the call never returns. The hook counts both threads' hits and parks only on the ParkHit-th, so neither a restart of parked nor interleaved passing point parks again.

The calling thread is QSBR-paused until both threads have joined and passes a quiescent state before returning, so it must not be paused already and must not hold a QSBR-protected pointer or a view into a tree across the call.

Returns
The number of times either thread hit point, or only parked's hits if the park was missed. Each call site's schedule fixes it, so callers pin it exactly: that is what shows an unexpected extra restart, or a write path that starts passing point.

◆ throws_bad_alloc()

template<typename Action>
bool unodb::test::throws_bad_alloc ( std::uint64_t fail_n,
const Action & action )
nodiscardnoexcept

Run action with the allocation failure injector armed to fail allocation number fail_n, and report whether it threw std::bad_alloc.

Keeps the armed scope around action alone: the guard is destroyed while the injected failure unwinds, so the handler below, and the caller's assertion on the result, both run disarmed. Asserting on the result afterwards, rather than wrapping action in an assertion, matters: a failing assertion builds its message with the injector still armed at its trip point, so the diagnostic would be replaced by an escaping std::bad_alloc.

Declared in debug builds only. Under NDEBUG the injector compiles away, where this would arm nothing and report false for every fail_n — a wrong answer rather than a skipped check, unlike must_not_allocate(). Every call site must therefore sit inside #ifndef NDEBUG, which the absent declaration enforces at compile time.

Warning
An assertion inside action runs armed past the trip point, so its failure escapes as std::bad_alloc and is reported here as the expected outcome, leaving the check unmade. Pause across such assertions.
Arms a process-wide injector; concurrent allocations can interfere.
Must not call must_not_allocate() or be called from it.
