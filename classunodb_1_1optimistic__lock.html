Detailed Description

Version-based optimistic lock that supports single-writer/multiple-readers concurrency without shared memory writes during read operations.

Writers bump the version counter and readers detect concurrent writes by comparing the version counter before and after the reads. Instances are non-copyable and non-moveable.

See Optimistic Locking for usage examples and protocols.

To support reusing the same code for single-threaded context too, there is a no-op counterpart: unodb::fake_optimistic_lock, enabling templatizing on the lock type and passing either class as needed.

Used for restoring OLC iterator state. It does not do any spin waits or even look at the current lock version. ◆ try_read_lock()

read_critical_section unodb::optimistic_lock::try_read_lock ( )
inlinenodiscardnoexcept

Acquire and return an optimistic_lock::read_critical_section for this lock.

This is done without writing anything on the lock, but it will spin if the lock is write-locked. It will return immediately if the lock is in obsolete state. In debug builds, this will maintain the open RCS counter.

Note
read_critical_section::must_restart must be called before the first protected data access to check for obsolete state.

◆ try_read_lock_no_wait()

read_critical_section unodb::optimistic_lock::try_read_lock_no_wait ( )
inlinenodiscardnoexcept

Acquire and return an optimistic_lock::read_critical_section for this lock, like try_read_lock(), but without waiting: if the lock is write-locked, return at once an RCS in the obsolete state, as for an obsolete lock.

A writer that already holds write locks uses this to lock one more node. Waiting there could deadlock against a writer that holds that node and waits for one of the caller's locks.

Note
read_critical_section::must_restart must be called before the first protected data access, and the caller must restart if it returns true.

Try to read unlock this lock by comparing the current version with locked_version.

Since read locking and unlocking does not affect the shared lock state, this only checks whether the lock version is equal to locked_version.

Return values
