Detailed Description

template<typename Key, typename Value, typename HeapTag>
class unodb::olc_db< Key, Value, HeapTag >

A thread-safe Adaptive Radix Tree that is synchronized using optimistic lock coupling.

At any time, at most two directly-related tree nodes can be write-locked by the insert algorithm and three by the delete algorithm. The lock used is optimistic lock (see optimistic_lock.hpp), where only writers lock and readers access nodes optimistically with node version checks. For deleted node reclamation, Quiescent State-Based Reclamation is used.

Whether an insert or upsert descent must restart because key_matches_prefix_to_end() holds for remaining_key and an inode's key prefix, shared_length being that prefix's prefix_match::shared_length.

Keys are prefix-free, so the key ends there only if the inode's prefix was rewritten in place after the descent checked the parent, leaving the descent at the inode's old depth. An I4 collapse lengthens it and moves the inode's version, or obsoletes the parent if it finished before the inode was read-locked. A prefix split shortens it and write-locks the parent. nodiscardprivate

Atomic chain cut: remove a leaf under a chain of single-child I4 nodes.

Locks the chain bottom-up, then atomically disconnects the entire chain from its parent (the "cut point") in a single child-pointer update. Chain nodes are locked at the versions the downward pass read, up to the first whose version moved. From there each node is read at its current version and must still lead to the node below it: a one-child I4 joins the chain, and the first other node becomes the cut-point parent, so a chain node that gained a child moves the cut point down. The operation restarts without modifying the tree if a node it re-reads is obsolete or no longer leads to the node below it, if it would replace the cut-point parent in its own parent and that parent has changed, if the root pointer it would rewrite no longer points to stk[0], or if the cut-point parent is an I4 that will collapse and the inode it would leave cannot be write-locked without waiting, since waiting could deadlock against another chain cut that holds it. After the cut, the cut-point parent is shrunk or collapsed as needed to maintain well-formedness (no single-child I4 except during chain insert). Disconnected nodes are reclaimed via QSBR.

Single-attempt insert.

For variable-length keys (key_view) only, two keys may share more than key_prefix_capacity (7) bytes at a given depth, causing their dispatch bytes to collide. When this happens, a single-child "chain" I4 node is created that consumes 7 prefix bytes + 1 dispatch byte, advancing depth by 8. The insert then restarts from the root. Subsequent attempts descend through the chain and either extend it (if keys still collide) or complete a normal two-child split.

Two-pass removal with chain cleanup for variable-length keys.

Pass 1 (downward): traverses from root to the target leaf, building a stack of inode entries with cached versions. Single-child I4 nodes are identified as chain members.

If the key is absent, inserts v and returns true without calling fn. If the key is present, invokes fn with a mutable reference to the existing value; the returned upsert_action determines whether the value is kept, updated, or erased. Returns false in this case.
